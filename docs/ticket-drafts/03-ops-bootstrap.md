# 03: Первичные Ops и обычное назначение

**What to build:** Server admin назначает первых Ops, после чего они могут назначать следующих через сайт.

**Blocked by:** 02: Magic link и минимальный профиль

**Status:** локальный ticket draft; в GitHub не опубликован.

**Implementation:** реализовано и проверено локально 2026-09-21.

## Acceptance criteria

- [x] При отсутствии Ops документированная bootstrap-команда назначает подтверждённых school sponsor пользователей.
- [x] Bootstrap при уже существующих Ops не используется как обычный путь назначения.
- [x] Действующий Ops назначает/подтверждает новых Ops внутри сайта; изменение роли записывается в журнал.
- [x] Обычный Member не может назначить роль ни через UI, ни прямым API.
- [x] Нет отдельного кабинета school sponsor; организационные условия описаны в инструкции.
- [x] Проверяются bootstrap и последующий нормальный путь с реальным сохранением роли.

## Проверка и границы

Срез включает необходимые изменения хранения, серверного поведения и пользовательского либо административного интерфейса. Проверять внешний результат, не внутреннее устройство. Предложенная основа: API с изолированной PostgreSQL и небольшое число браузерных сценариев; пользователь подтвердил CLI bootstrap + HTTP API + настоящую PostgreSQL + браузер. Все добавленные пользовательские тексты доступны на DE/EN, авторский контент не переводится автоматически.


## Результат

Bootstrap-команда требует уже подтверждённого Member и атрибуции school sponsor / server admin. Назначения сериализуются; при любом существующем Ops bootstrap отклоняется. Обычное назначение выполняется на `/ops`, доступном из профиля Ops. Роль и запись журнала сохраняются атомарно; email не включается в каталог. Recovery остаётся отдельной задачей 19.

Инструкция: [назначение Ops](../operations/ops-appointments.md).

Проверки: 18 API/CLI-тестов, 6 браузерных сценариев, typecheck, lint, build. Standards review: замечание к дублированию тестовой инфраструктуры исправлено; оставшихся замечаний нет. Spec review: замечаний нет.
