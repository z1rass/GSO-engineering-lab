# 05: Создание Project с owner

**What to build:** Member создаёт собственный Project или реализацию Idea и сразу становится Activity Owner.

**Blocked by:** 04: Публичные идеи без обязательств

**Status:** draft — ожидает согласования разбиения и выбора трекера; не опубликовано.

## Acceptance criteria

- [ ] Создание, список и страница Project работают с целью, описанием, tech stack и ссылками на repository/documentation.
- [ ] Creator сразу единственный owner; нет обязательного Ops approval и отдельной глобальной роли организатора.
- [ ] Idea необязательна; несколько Projects могут ссылаться на одну Idea без изменения её автора или обязательств.
- [ ] Owner/Ops редактируют Project; другие Members не получают эти права; Visitor не получает identity owner.
- [ ] Поддерживаются подготовка и переход в работу; вступление команды и завершение поставляются зависимыми задачами.
- [ ] Текст материалов и вручную добавленная Discord-ссылка доступны owner для редактирования; приватные инструкции не попадают гостям.
- [ ] Проверки проходят через создание, persisted чтение, переход и запреты редактирования.

## Проверка и границы

Срез включает необходимые изменения хранения, серверного поведения и пользовательского либо административного интерфейса. Проверять внешний результат, не внутреннее устройство. Предложенная основа: API с изолированной PostgreSQL и небольшое число браузерных сценариев; окончательное согласование границ тестирования ещё ожидается. Все добавленные пользовательские тексты доступны на DE/EN, авторский контент не переводится автоматически.
