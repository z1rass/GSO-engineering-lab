# 02: Magic link и минимальный профиль

**What to build:** User подтверждает школьную принадлежность и получает доступ Member с минимальным профилем.

**Blocked by:** 01: Первый работающий экран Season

**Status:** локальный ticket draft; в GitHub не опубликован.

**Implementation:** реализовано и проверено локально 2026-09-21.

## Acceptance criteria

- [x] Magic link отправляется только на точный домен @gso.schule.koeln; проверяется владение адресом, а не только введённая строка.
- [x] Ссылки одноразовые и ограничены по времени; сессия истекает; новый вход требует нового подтверждения.
- [x] Для локальной проверки письмо доступно через тестовую доставку, без реальной школьной учётки в seed.
- [x] Имя и школьная почта обязательны; направление, год и интересы необязательны; профиль редактируется владельцем.
- [x] User независим от Member/Alumni; утрата школьной принадлежности сама по себе не удаляет аккаунт/историю. Вход Alumni не реализуется.
- [x] Проверяются secure-cookie/CSRF механизмы, неверные и просроченные ссылки, повторное использование, истечение сессии и запрет чужого редактирования.

## Проверка и границы

Срез включает необходимые изменения хранения, серверного поведения и пользовательского либо административного интерфейса. Проверять внешний результат, не внутреннее устройство. Предложенная основа: API с изолированной PostgreSQL и небольшое число браузерных сценариев; пользователь подтвердил API + настоящую PostgreSQL + SMTP/Mailpit + браузерный сценарий. Все добавленные пользовательские тексты доступны на DE/EN, авторский контент не переводится автоматически.

## Решения до реализации

Better Auth + Drizzle; SMTP через Nodemailer, локальная доставка в Mailpit. Ссылка — 15 минут, одно использование; сессия — 7 дней без продления. Лимиты сохраняются в PostgreSQL. Проверочные адреса генерируются на школьном домене только в изолированных тестах/локальном Mailpit, без bypass проверки владения. Production требует отдельной SMTP-конфигурации и HTTPS. Подробности и ограничения прокси — в README.

Проверено: 13 API-тестов (из них 9 для auth), 5 браузерных сценариев, typecheck, lint, build; визуальная проверка desktop/mobile. Standards и Spec review: замечаний нет.
