# 14: Seasons и продолжение Project

**What to build:** Ops ведут Seasons, а owner продолжает Project в следующем Season без пересоздания.

**Blocked by:** 05: Создание Project с owner; 06: Создание Event в подготовке

**Status:** реализовано локально 2026-09-22; draft не опубликован в GitHub.

## Acceptance criteria

- [x] Ops создают/редактируют Seasons, управляют их состоянием; Member не может это делать.
- [x] Season показывает свои Events и Projects; homepage использует текущий Season и новые Activity.
- [x] Привязка Activity необязательна; продолжение Project сохраняет его идентичность, команду и задачи.
- [x] Связи с прошлыми Seasons сохраняются; завершение Season само по себе не закрывает Project.
- [x] Бейдж показывает действительную историю, без выдуманных промежуточных Seasons.
- [x] Проверки подтверждают продолжение, публичную выдачу и отсутствие потери существующих данных.

## Проверка и границы

Согласованные границы: HTTP API с настоящей изолированной PostgreSQL и браузерный сценарий. Проверять внешний результат, не внутреннее устройство. Все добавленные пользовательские тексты доступны на DE/EN, авторский контент не переводится автоматически.

## Результат

Ops управляют Seasons через `/ops/seasons`; черновики скрыты от публичной выдачи. База гарантирует уникальные номера и единственный ACTIVE Season. Публичные страницы показывают связанные Events/Projects, главная — текущий Season и шесть новых открытых Activity.

Owner связывает Activity с UPCOMING/ACTIVE Season со страницы Activity. Event принадлежит одному Season, Project может продолжаться в нескольких. Связи сохраняются без пересоздания Project, команды или Tasks; завершение Season не закрывает Activity. Бейджи перечисляют фактические номера, включая разрывы. Привязка остаётся необязательной.

Проверки: typecheck, lint, build; 58 API/CLI tests и 18 браузерных сценариев прошли. Code review по Standards и Spec — без замечаний. Переход по якорю к About дожидается загрузки Season и новых Activity, чтобы раздел оставался в области просмотра.
