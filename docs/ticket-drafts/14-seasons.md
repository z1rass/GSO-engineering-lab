# 14: Seasons и продолжение Project

**What to build:** Ops ведут Seasons, а owner продолжает Project в следующем Season без пересоздания.

**Blocked by:** 05: Создание Project с owner; 06: Создание Event в подготовке

**Status:** draft — ожидает согласования разбиения и выбора трекера; не опубликовано.

## Acceptance criteria

- [ ] Ops создают/редактируют Seasons, управляют их состоянием; Member не может это делать.
- [ ] Season показывает свои Events и Projects; homepage использует текущий Season и новые Activity.
- [ ] Привязка Activity необязательна; продолжение Project сохраняет его идентичность, команду и задачи.
- [ ] Связи с прошлыми Seasons сохраняются; завершение Season само по себе не закрывает Project.
- [ ] Бейдж показывает действительную историю, без выдуманных промежуточных Seasons.
- [ ] Проверки подтверждают продолжение, публичную выдачу и отсутствие потери существующих данных.

## Проверка и границы

Срез включает необходимые изменения хранения, серверного поведения и пользовательского либо административного интерфейса. Проверять внешний результат, не внутреннее устройство. Предложенная основа: API с изолированной PostgreSQL и небольшое число браузерных сценариев; окончательное согласование границ тестирования ещё ожидается. Все добавленные пользовательские тексты доступны на DE/EN, авторский контент не переводится автоматически.
