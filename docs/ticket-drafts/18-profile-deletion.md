# 18: Удаление профиля через Ops

**What to build:** Ops выполняют запрос удаления, сохранив результаты без персональной идентичности.

**Blocked by:** 13: Завершение, отмена и прошедшие; 15: Личный обзор участия и ответственности; 16: Приватный Club Network; 17: Скрытие контента и блокировка User

**Status:** draft — ожидает согласования разбиения и выбора трекера; не опубликовано.

## Acceptance criteria

- [ ] Активное ownership сначала передаётся или отменяется; удаление не оставляет активную Activity без ответственности.
- [ ] Профиль и связанные персональные данные удаляются, сессии перестают работать.
- [ ] Неперсональные результаты сохраняются с подписью «Удалённый участник», а не старым именем/email.
- [ ] Учтены participation, задачи, истории назначений и attribution записей Club Network без удаления чужих независимых контактов.
- [ ] Нет самостоятельного пользовательского интерфейса удаления; процесс документирован для Ops.
- [ ] Проверки включают доступ по старой сессии, связанные выдачи и сохранение результатов.

## Проверка и границы

Срез включает необходимые изменения хранения, серверного поведения и пользовательского либо административного интерфейса. Проверять внешний результат, не внутреннее устройство. Предложенная основа: API с изолированной PostgreSQL и небольшое число браузерных сценариев; окончательное согласование границ тестирования ещё ожидается. Все добавленные пользовательские тексты доступны на DE/EN, авторский контент не переводится автоматически.

## Решения до реализации

До реализации определить удаление персональных данных из журналов, свободного текста и backup, включая поведение после restore.
