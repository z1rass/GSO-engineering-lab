# 10: Going и повторное подтверждение при переносе

**What to build:** Owner открывает регистрацию, Member записывается, а перенос возвращает участника в Interested.

**Blocked by:** 07: Interested без регистрации; 09: Простой запрос помещения

**Status:** локальный ticket draft; в GitHub не опубликован.

**Implementation:** реализовано локально 2026-09-22.

## Acceptance criteria

- [x] Going открывается при определённых дате, времени, месте и подтверждённом Room Request, когда помещение требуется.
- [x] Event без потребности в школьном помещении открывает owner самостоятельно.
- [x] Можно записаться и отказаться; нет лимита мест, листа ожидания и дублирования регистраций.
- [x] Смена даты или времени переводит существующие Going в Interested без частичного обновления.
- [x] Изменение описания не сбрасывает Going; перенос/отмена сообщаются вручную в Discord.
- [x] Проверяются условия открытия, права, повторные действия, сброс регистрации и сохранение её при обычном редактировании.

## Проверка и границы

Срез включает необходимые изменения хранения, серверного поведения и пользовательского либо административного интерфейса. Проверять внешний результат, не внутреннее устройство. Предложенная основа: API с изолированной PostgreSQL и небольшое число браузерных сценариев; пользователь подтвердил HTTP API + настоящую PostgreSQL + браузер для web-задач. Все добавленные пользовательские тексты доступны на DE/EN, авторский контент не переводится автоматически.



## Результат

Owner открывает Going после заполнения даты, начала, конца и общего места. Обязательность школьного помещения задаётся флагом либо наличием Room Request: требуется окончательное подтверждение, совпадение точной комнаты и вхождение Event в согласованный временной интервал. Наличие заявки нельзя обойти снятием флага. Ops редактируют Event, но открыть регистрацию другого owner не могут.

Going записывает только текущего Member, без дублей и лимита мест. Публичны состояние регистрации и количество; список имён доступен Members. Interested остаётся независимым.

Изменение даты/времени переносит Going в Interested и закрывает регистрацию атомарно; изменение описания её сохраняет. Отсутствующая дата окончания эквивалентна дате начала. Event-row lock сериализует запись, открытие и редактирование. UI DE/EN предупреждает о переносе и ручной коммуникации через Discord. Новая заявка помещения после открытия также возвращает Event в подготовку до готовности условий; сама заявка не сбрасывает Going без переноса даты/времени.

Проверки: 45 API/CLI-тестов, 14 браузерных сценариев, typecheck, lint и build. После Spec review исправлено обновление Event/Going после создания запроса помещения и добавлен браузерный regression-сценарий. Добавлена HTTP-проверка no-store для приватной выдачи участников. Standards: замечаний нет.

Повторное Spec review подтвердило исправление; оставшихся замечаний нет. Затронутые API/браузерные сценарии повторно прошли после исправления.
