# 16: Приватный Club Network

**What to build:** Ops сохраняют и обновляют контакты клуба для будущих приглашений.

**Blocked by:** 03: Первичные Ops и обычное назначение

**Status:** реализовано локально 2026-09-22; draft не опубликован в GitHub.

## Acceptance criteria

- [x] Ops могут создавать, читать, редактировать и удалять записи контактов.
- [x] Контакт поддерживает имя, компанию, профессиональную роль, темы, заметки, способ связи и происхождение записи.
- [x] Visitor и Member не получают записи или contact emails ни прямым API, ни через публичные страницы.
- [x] Member обращается за помощью к Ops через Discord; отдельная система запросов не появляется.
- [x] Проверки матрицы доступа и persisted CRUD защищают базу от утечек.

## Проверка и границы

Использованы ранее согласованные границы: HTTP API с настоящей изолированной PostgreSQL и браузерный сценарий. Интерфейс DE/EN; авторский контент не переводится.

## Результат

Страница `/network` открывается из Ops. Контакты поддерживают имя, компанию, профессиональную роль, темы, заметки, способ связи и источник знакомства. Автор добавления и timestamps определяются сервером; правки не заменяют автора. Удаление в интерфейсе требует отдельного подтверждения и удаляет контакт целиком.

API находится под `/api/ops/network`: GET/POST списка, GET/PATCH/DELETE конкретного ID. Все маршруты наследуют текущую проверку Member/Ops, `no-store` и Origin для изменений. Текст контакта не превращается в произвольную активную ссылку; публичные API не читают таблицу `contacts`. Member/Visitor видят только отказ и рекомендацию обратиться к Ops вручную через Discord. Новых запросов, сообщений и уведомлений нет.

Проверки: typecheck, lint, build; 64 API/CLI tests и 22 браузерных сценария прошли. Review Standards и Spec — без замечаний.
